What's new

Tag a passage grammar and its name becomes a macro that prints a random line from it, with keep, reroll, and JavaScript helpers. See Grammar.

Getting started

Install Duplex

Twine 2 Desktop

  1. Download or clone the repository and keep it somewhere permanent.
  2. Open Twine → Story Formats → Add.
  3. Paste the full file URL to format.js (inside the Duplex-1/duplex-format folder).
  4. Select Duplex 1.9.0 for your story.
Linux example
file:///home/you/duplex-story-format/Duplex-1/duplex-format/format.js

Browser Twine may block local file URLs. Use Twine Desktop or host the format online.

Tweego

Each format lives in its own folder under a story-formats folder. The folder's name is the ID you pass to -f.

Project layout
storyformats/
└── duplex-1/
    └── format.js
my-story/
└── src/
    └── story.twee
Shell
export TWEEGO_PATH="$HOME/storyformats"
tweego --list-formats
tweego -f duplex-1 -o story.html src/

Install on Android (Termux)

Tweego has no official Android download, but Termux packages it, so it installs in one command. Get Termux from F-Droid or GitHub, not the Play Store.

  1. Install Tweego and Git You should see tweego, v2.1.1.
    Termux
    pkg update
pkg install tweego git
tweego --version

    If pkg install tweego isn't available, build it with Go instead: pkg install golang, then go install github.com/tmedwards/tweego@master, then check ls ~/go/bin lists tweego. Add Go's folder to your PATH with exactly echo 'export PATH="$PATH:$HOME/go/bin"' >> ~/.bashrc, with no backslashes before the $ signs, then run source ~/.bashrc.

  2. Add Duplex as a story format
    Termux
    cd ~
git clone https://github.com/Techy-Nature/duplex-story-format.git
mkdir -p ~/storyformats/duplex-1
cp "duplex-story-format/Duplex-1/duplex-format/format.js" ~/storyformats/duplex-1/
echo 'export TWEEGO_PATH="$HOME/storyformats"' >> ~/.bashrc
source ~/.bashrc
tweego --list-formats
  3. Build your story Add -w to rebuild every time you save.
    Termux
    cd ~/stories/my-story
tweego -f duplex-1 -o story.html src/
  4. Play it Serve the folder and open http://localhost:8080/story.html in your phone's browser.
    Termux
    pkg install python
python -m http.server 8080

The full Termux guide covers the Go fallback, fixing a broken PATH, updating Duplex, building into Downloads, converting an existing Twine story to Twee, and troubleshooting.

Scrolling

Append mode

Twine

Page-by-page

Replace mode

Navigation clears the previous passage before showing the next.

Twine

The value may be conditional, such as <<set $passageMode = $useScrolling ? "append" : "replace">>. Story JavaScript may set Config.displayMode, which takes priority over story variables.

Authoring helpers

Comments and Markdown

Passage comments

Use // for a single-line comment, /* ... */ for a block comment, or the <<comment>> container. Comments are not displayed, and macros inside them are not evaluated.

Twine
// A whole-line note
The nest is empty. // A trailing note

/* This note may
span several lines. */

<<comment>>
  <<set $hidden = true>>
  None of this is displayed or run.
<</comment>>

A // comment starts at the beginning of a line or after whitespace, so URLs such as https://example.com remain intact.

Markdown

Wrap Markdown in <<markdown>>...<</markdown>>, or tag a whole passage markdown. It supports headings, bold and italic emphasis, inline code, links, images, block quotes, and ordered or unordered lists. Duplex variables and macros are processed inside the result.

Twine
<<markdown>>
# Field notes

**Species:** $birdName

- Seen at dusk
- [Read more](https://example.com/birds)

> <<= $observation>>
<</markdown>>
// commentIgnore text through the end of the line.
/* comment */Ignore a comment spanning part of a line or multiple lines.
<<comment>>…<</comment>>Ignore a container and do not evaluate its macros.
<<markdown>>…<</markdown>>Render supported Markdown while processing Duplex variables and macros.
[markdown] tagRender the whole passage as Markdown.

Keyboard and preferences

Shortcuts and Settings

Readers can change every shortcut in Settings: select the shortcut button, then press one or two keys. The new value is saved straight away for that story. Shortcuts never fire while the reader is typing in an input.

Shift+IOpen Inventory.
Shift+AltOpen Settings.
Shift+BackspaceReset the story.
Shift+SSkip the current content-tagged passage.
EnterSelect the focused control.
1 … 9, 0Choose the first through ninth visible link; 0 chooses the last link.

The Settings dialog

If a StorySettings passage exists, its contents appear at the top of Settings. Below it come the shortcut rows and, when the story uses content tags, the Content panel from content skipping.

Add your own shortcuts

Story JavaScript
Duplex.shortcuts.add('journal', {
  label: 'Open journal',
  defaultShortcut: 'Shift+J',
  selector: '#open-journal'
});

Duplex.shortcuts.add('map', {
  label: 'Open map',
  defaultShortcut: 'M',
  action: () => setup.openMap()
});

IDs must be unique. Each shortcut needs a label, a default of no more than two keys, and either an action function or a CSS selector for the button to press. Duplex.shortcuts.get(id) and Duplex.shortcuts.list() report the reader's current bindings, and set(id, shortcut) is available for author tooling.

Items, bags, and rooms

Inventory

Inventory is a JSON-serializable hierarchy of named items and stable, named bag instances. Item stacks hold up to 1000 units. Compatible ordinary bags also stack up to 1000 while empty; adding an item or child bag automatically splits one bag from the stack so every populated bag has its own identity.

Nested bags

  • Populated bags may contain item stacks and other populated bags to any valid depth.
  • Moving a bag moves its complete nested branch without flattening or redistributing it.
  • A single click opens a bag and shows its immediate contents.
  • A double-click unpacks its immediate contents into the parent.
  • The visible Take Everything action is the accessible alternative to double-clicking.

Rooms are locations

  • A safe room preserves its complete nested hierarchy when the player leaves.
  • A danger room recursively clears all of its contents on exit.
  • Room bags are fixed, top-level locations. Unlike movable ordinary bags, they cannot be put inside, moved into, or unpacked into another bag.
Stacks and splitting. Define each item by name, then add quantities from 1 through 1000. Empty bags stack only when their definition, name, and properties are compatible. A populated bag is always a single instance.

Define and build an inventory

Story JavaScript
Inventory.defineItem("vial", { name: "Healing vial" });

const pack = Inventory.createBag("travel-pack", {
  name: "Travel pack",
  properties: { capacity: 12 }
});
const pouch = Inventory.createBag("medicine-pouch", {
  name: "Medicine pouch",
  parentId: pack.id,
  quantity: 3
});
const camp = Inventory.createRoom("camp", {
  name: "Camp",
  safe: true
});

Inventory.addItem(pouch.id, "vial", 6);
Inventory.moveBag(pouch.id, pack.id);

Open, unpack, and enter rooms

Story JavaScript
Inventory.openBag(pack.id);              // Show this bag directly.
Inventory.unpackBag(pouch.id, pack.id);  // Transfer immediate contents.

Inventory.enterRoom(camp.id);
Inventory.leaveRoom(camp.id);            // Safe room hierarchy remains.

Inventory.open();                        // Open the main Inventory browser.
Inventory.defineItem(id, definition)Register a named item definition.
Inventory.createBag(definition, options?)Create or stack compatible empty ordinary bags.
Inventory.createRoom(definition, options?)Create a fixed top-level safe or danger room bag.
Inventory.addItem(bagId, item, quantity?)Add up to 1000 units, splitting a bag stack when needed.
Inventory.moveBag(sourceId, destinationId)Move an ordinary bag and its complete nested branch.
Inventory.openBag(id)Show one bag and its immediate rows.
Inventory.unpackBag(id, destinationId)Move only the immediate items and child bags.
Inventory.enterRoom(id)Enter a top-level room location.
Inventory.leaveRoom(id)Leave it, preserving safe rooms or clearing danger rooms recursively.
Inventory.open()Open the built-in Inventory browser.
Hierarchy changes are guarded and atomic.

A bag cannot become its own ancestor or be moved or unpacked into one of its descendants. Duplex validates ancestry, room, compatibility, and capacity restrictions before changing anything. If unpacking would fail any check, the entire operation fails and the source and destination remain unchanged.

Data-only extensions

Mods

Quest mods as .mod files (1.9.0)

The easiest way to add to a story. A .mod file is plain text: optional settings at the top, then Twee-like sections. :: after Passage and :: before Passage add text around a story passage, any other :: line adds a place of the mod's own, and :: items (or any :: line tagged [items]) holds a JSON array of items. The mod's name is its id; without a Mod: line, the file name is used.

Haunted House.mod
Mod: Haunted House
Version: 1.0.0
Author: Example

:: after Town Square
[[Investigate the old house->Old House]]

:: Old House [skip unsafe-room]
The door creaks open onto a dark hall.
[[Leave->Town Square]]

:: items
[{ "id": "brass-key", "name": "Brass Key" }]

Import it from Mods → Import mod. Mistakes are reported with their line number and nothing is installed. Story code uses the name as the id: Duplex.mods.createItem("Haunted House", "brass-key"). See the step-by-step .mod guide.

JSON mods

Duplex can install validated JSON manifests containing item definitions and restricted passage extensions. Choose Mods in the left story bar or call Duplex.mods.open() to import, enable, disable, or remove a mod. Installed mods are kept per story in IndexedDB; importing one never awards an item or creates $inventory.

Create and add an item

Story JavaScript
const item = Duplex.mods.createItem(
  "neston.more-birds",
  "nighthawk-feather",
  { quantity: 1 }
);

Duplex.inventory.addItem(playerBagId, item);

Safe, namespaced data

  • Manifest schema 1 requires a name and version. The ID defaults to the name, and items default to an empty array.
  • Item identities use mod-id:item-id.
  • Disabled or removed mods do not serve definitions, but existing inventory items remain intact.
  • Saves record enabled mod IDs and versions and warn about missing, disabled, or different versions.

Restricted passage extensions

Schema 1 mods may use passageExtensions to add Duplex markup before or after an existing base-story passage. Extensions run as virtual mod restricted passages, never alter the original text, disappear while their mod is disabled, and use stored import order followed by manifest order.

Mod manifest
{
  "schema": 1,
  "id": "example.quest-pack",
  "name": "Example Quest Pack",
  "version": "1.0.0",
  "items": [],
  "passageExtensions": [{
    "id": "haunted-house-hook",
    "target": "Town Square",
    "placement": "after",
    "content": "<<if $hauntedHouseStarted>>[[Investigate the old house->Old House]]<</if>>"
  }]
}

Targets must already exist and cannot be protected story UI or initialization passages, or passages tagged widget, grammar, script, or stylesheet. Restricted mode follows nested includes and uses a limited expression interpreter rather than JavaScript. Conditionals, switches, printing, links, controls, includes, literals, variables, safe operators, tags, and controlled variable assignment are supported; browser APIs, arbitrary calls, scripts, widgets, and executable-code registration are blocked. Restricted HTML and Markdown output is sanitized. <<skipto>> and <<skipsummary>> are ignored inside extensions.

Data only. JavaScript mods, CSS, assets, archives, and network downloads are not supported. Mod text is never executed as JavaScript. See the mod guide and its example manifest.

Player safety

Saves and portable backups

Duplex keeps one browser save per story. Players can export that progress as a JSON file and import it in another browser or device. Imported files are checked for a Duplex marker, supported schema, matching story identity, valid history, and known passages before progress is replaced. The complete inventory hierarchy takes part in Save, import/export, Back, Restart, and history restoration.

Save dialog

  • Save stores progress in this browser.
  • Load restores the browser save.
  • Export downloads a portable JSON backup.
  • Import validates and restores a backup.
  • Delete removes the browser save.

JavaScript API

Save.load()Restore it.
Save.delete()Remove it.
Save.export(filename?)Download JSON.
Save.import(source)Import JSON, an object, or a File.
Save.serialize()Return JSON text.
Save.parse(text)Validate JSON text.
Story JavaScript

// File imports return a promise.

Loaded saves have any JavaScript stripped out, and forged controls in a save file are rejected, so a shared save file cannot run code. The API is available as both Save and Duplex.Save. Duplex has one browser slot rather than SugarCube’s multi-slot system.

Random words · 1.6.0+

Grammar

Tag a passage grammar to make a word list: one option per line, with blank lines and // lines skipped. Repeat a line to make it more likely. The passage name becomes a macro that prints a random option inline.

Word list

Twine
:: wolf-like [grammar]
wolfish
wolfin
wolf-like
lupine

Use it

Twine
Its <<wolf-like>> eyes caught the light.
<<wolf-like.upperFirst>> shapes circle the fire.

<<run Grammar.keep("wolf-like", "$wolfWord")>>
The $wolfWord one returns.

Macros

<<name>>A random option, new every time.
<<name keep>>Picks once, then repeats it. Stored in $grammarKept, so saves keep it.
<<name reroll>>Picks a new kept option.
<<grammar "name">>Generic form for any list, including names that clash with a macro. keep and reroll work here too.

Capital letters (1.8.0)

<<name.upperFirst>>Capitalizes the first letter (bird → Bird); the rest stays as written.
<<name.upper>>Whole option in capitals (BIRD).
<<name.lower>>Whole option in lowercase (bird).
<<grammar "name.upper">>The generic form takes a case style too, as a suffix or as <<grammar "name" upper>>.

Case styles combine with keep and reroll (<<name.upperFirst keep>>) and work inside widgets.

JavaScript

Grammar.pick(name)Return a pick as plain text, with nested lists and variables filled in. Names take case suffixes: Grammar.pick("animal.upperFirst").
Grammar.save(name, "$var")Store a new pick as plain text.
Grammar.keep(name, "$var")Store a pick only if the variable is empty.
Grammar.define(name, options)Create or replace a list from code.
Config.grammar.avoidRepeatsDefault true: lists of three or more never repeat the previous pick.

Options are processed like passage text, so they can hold variables, links, HTML, and other grammar macros, including their own name for recursive lists (nesting stops at 20 levels). Use hyphens, not underscores, in list names, because _word reads as a temporary variable, and avoid dots, since . starts a case style. The full API is pick, pickRaw, save, keep, kept, reroll, forget, has, list, names, and define, on Grammar or Duplex.grammar.

Reader comfort · 1.7.0+

Skip tagged content

Duplex can warn readers about passages with sensitive content and let them skip those passages, one at a time with a Skip button or automatically for whole categories they choose in Settings. Skipping hides a passage's text but still runs it, so every <<set>> and inventory change still happens and your variables stay consistent.

  1. Tag the passage Add one or more content tags. Capital letters don't matter. Use skip for any optional scene, such as a long recap.
    skipsexviolencegoreabuseself-harmdrugsdeath
    A notice with a Skip button appears under the passage title.
  2. Choose where Skip goes Duplex uses the passage named by <<skipto>>, or else the first link that leads somewhere else. With neither, the button is disabled. <<skipto>> prints nothing and accepts a name or an expression such as <<skipto $nextScene>>.
  3. Add a summary (optional) <<skipsummary>> is shown only when the passage is skipped automatically, so readers don't lose the plot. It may contain links and variables.
  4. Readers choose Settings → Content lists every content tag the story uses, each with a checkbox. Checked tags are skipped automatically, saved per story in the reader's browser. A skipped passage shows Continue and Show anyway. Shift+S skips the current tagged passage.
Twine
:: The Ambush [violence gore]
<<skipto "Clearing">>
<<skipsummary>>You drive off the shades, but you are wounded.<</skipsummary>>
<<set $health -= 2>>
The shades tear at you. Steel flashes.

[[Fight back->Clearing]]
[[Flee->Riverbank]]

Configure it

Every setting lives on Config.skip in Story JavaScript. Change only what you need.

Story JavaScript
// Add your own tags and their reader-facing names.
Config.skip.tags.push('spiders', 'body-horror');
Config.skip.labels.spiders = 'Spiders';
Config.skip.labels['body-horror'] = 'Body horror';

// Skip these automatically until the reader changes the setting.
Config.skip.defaults = ['gore'];

// Hide the notice on passages that are not being skipped.
Config.skip.showNotice = false;

// Jump straight past auto-skipped passages instead of showing Continue.
Config.skip.autoAdvance = true;

// List every tag in Config.skip.tags in Settings, even unused ones.
Config.skip.showAllTags = true;

Things to know. Only the passage the reader navigates to is checked, so tag the outer passage rather than one pulled in with <<include>>. UI passages such as StoryInit, StoryMenu, and StorySettings are never skipped. With autoAdvance, Duplex follows at most 20 auto-skipped passages in a row.

Passage metadata

Check passage tags

In StoryInit, explicitly name the passage because no ordinary passage is rendering yet.

Twine
<<if tags("Start").includes("scrolling")>>
  <<set $passageMode = "append">>
<<elseif hasTag("Start", "pages")>>
  <<set $passageMode = "replace">>
<<else>>
  <<set $passageMode = "replace">>
<</if>>

Inside an ordinary rendering passage, omit the title:

Twine
<<if hasTag("forest")>>
  You are beneath the trees.
<</if>>
Current tags: <<= tags().join(", ")>>

Unknown passages return an empty tag array. JavaScript may use Duplex.tags() and Duplex.hasTag().
