Authoring helpers

Comments and Markdown

Passage comments

Use // for a single-line comment, /* ... */ for a block comment, or the <<comment>> container. Comments are not displayed, and macros inside them are not evaluated.

Twine
// A whole-line note
The nest is empty. // A trailing note

/* This note may
span several lines. */

<<comment>>
  <<set $hidden = true>>
  None of this is displayed or run.
<</comment>>

A // comment starts at the beginning of a line or after whitespace, so URLs such as https://example.com remain intact.

Markdown container

Wrap Markdown in <<markdown>>...<</markdown>>. It supports headings, bold and italic emphasis, inline code, links, images, block quotes, and ordered or unordered lists. Duplex variables and macros are processed inside the result.

Twine
<<markdown>>
# Field notes

**Species:** $birdName

- Seen at dusk
- [Read more](https://example.com/birds)

> <<= $observation>>
<</markdown>>
// commentIgnore text through the end of the line.
/* comment */Ignore a comment spanning part of a line or multiple lines.
<<comment>>…<</comment>>Ignore a container and do not evaluate its macros.
<<markdown>>…<</markdown>>Render supported Markdown while processing Duplex variables and macros.

Items, bags, and rooms

Inventory

Inventory is a JSON-serializable hierarchy of named items and stable, named bag instances. Item stacks hold up to 1000 units. Compatible ordinary bags also stack up to 1000 while empty; adding an item or child bag automatically splits one bag from the stack so every populated bag has its own identity.

Nested bags

  • Populated bags may contain item stacks and other populated bags to any valid depth.
  • Moving a bag moves its complete nested branch without flattening or redistributing it.
  • A single click opens a bag and shows its immediate contents.
  • A double-click unpacks its immediate contents into the parent.
  • The visible Take Everything action is the accessible alternative to double-clicking.

Rooms are locations

  • A safe room preserves its complete nested hierarchy when the player leaves.
  • A danger room recursively clears all of its contents on exit.
  • Room bags are fixed, top-level locations. Unlike movable ordinary bags, they cannot be put inside, moved into, or unpacked into another bag.
Stacks and splitting. Define each item by name, then add quantities from 1 through 1000. Empty bags stack only when their definition, name, and properties are compatible. A populated bag is always a single instance.

Define and build an inventory

Story JavaScript
Inventory.defineItem("vial", { name: "Healing vial" });

const pack = Inventory.createBag("travel-pack", {
  name: "Travel pack",
  properties: { capacity: 12 }
});
const pouch = Inventory.createBag("medicine-pouch", {
  name: "Medicine pouch",
  parentId: pack.id,
  quantity: 3
});
const camp = Inventory.createRoom("camp", {
  name: "Camp",
  safe: true
});

Inventory.addItem(pouch.id, "vial", 6);
Inventory.moveBag(pouch.id, pack.id);

Open, unpack, and enter rooms

Story JavaScript
Inventory.openBag(pack.id);              // Show this bag directly.
Inventory.unpackBag(pouch.id, pack.id);  // Transfer immediate contents.

Inventory.enterRoom(camp.id);
Inventory.leaveRoom(camp.id);            // Safe room hierarchy remains.

Inventory.open();                        // Open the main Inventory browser.
Inventory.defineItem(id, definition)Register a named item definition.
Inventory.createBag(definition, options?)Create or stack compatible empty ordinary bags.
Inventory.createRoom(definition, options?)Create a fixed top-level safe or danger room bag.
Inventory.addItem(bagId, item, quantity?)Add up to 1000 units, splitting a bag stack when needed.
Inventory.moveBag(sourceId, destinationId)Move an ordinary bag and its complete nested branch.
Inventory.openBag(id)Show one bag and its immediate rows.
Inventory.unpackBag(id, destinationId)Move only the immediate items and child bags.
Inventory.enterRoom(id)Enter a top-level room location.
Inventory.leaveRoom(id)Leave it, preserving safe rooms or clearing danger rooms recursively.
Inventory.open()Open the built-in Inventory browser.
Hierarchy changes are guarded and atomic.

A bag cannot become its own ancestor or be moved or unpacked into one of its descendants. Duplex validates ancestry, room, compatibility, and capacity restrictions before changing anything. If unpacking would fail any check, the entire operation fails and the source and destination remain unchanged.

Data-only extensions

JSON item mods

Duplex 1.5.0 can install validated JSON manifests containing item definitions. Choose Mods in the left story bar or call Duplex.mods.open() to import, enable, disable, or remove a mod. Installed mods are kept per story in IndexedDB; importing one never awards an item or creates $inventory.

Create and add an item

Story JavaScript
const item = Duplex.mods.createItem(
  "neston.more-birds",
  "nighthawk-feather",
  { quantity: 1 }
);

Duplex.inventory.addItem(playerBagId, item);

Safe, namespaced data

  • Manifest schema 1 requires mod ID, name, version, and an items array.
  • Item identities use mod-id:item-id.
  • Disabled or removed mods do not serve definitions, but existing inventory items remain intact.
  • Saves record enabled mod IDs and versions and warn about missing, disabled, or different versions.

Data only. JavaScript mods, CSS, passages, assets, archives, and network downloads are not supported. Mod text is never executed.

Player safety

Saves and portable backups

Duplex keeps one browser save per story. Players can export that progress as a JSON file and import it in another browser or device. Imported files are checked for a Duplex marker, supported schema, matching story identity, valid history, and known passages before progress is replaced. The complete JSON-serializable inventory hierarchy participates in Save, import/export, Back, Restart, and history restoration, including every nested item, ordinary bag, and room tree.

Save dialog

  • Save stores progress in this browser.
  • Load restores the browser save.
  • Export downloads a portable JSON backup.
  • Import validates and restores a backup.
  • Delete removes the browser save.

Passage metadata

Check passage tags

In StoryInit, explicitly name the passage because no ordinary passage is rendering yet.

Twine
<<if tags("Start").includes("scrolling")>>
  <<set $passageMode = "append">>
<<elseif hasTag("Start", "pages")>>
  <<set $passageMode = "replace">>
<<else>>
  <<set $passageMode = "replace">>
<</if>>

Inside an ordinary rendering passage, omit the title:

Twine
<<if hasTag("forest")>>
  You are beneath the trees.
<</if>>
Current tags: <<= tags().join(", ")>>

Unknown passages return an empty tag array. JavaScript may use Duplex.tags() and Duplex.hasTag().

Restricted mod passage extensions

Schema 1 JSON mods may use passageExtensions to add Duplex markup before or after an existing base-story passage. Extensions run as virtual mod restricted passages, never alter the original text, disappear while their mod is disabled, and use stored import order followed by manifest order.

{
  "schema": 1,
  "id": "example.quest-pack",
  "name": "Example Quest Pack",
  "version": "1.0.0",
  "items": [],
  "passageExtensions": [{
    "id": "haunted-house-hook",
    "target": "Town Square",
    "placement": "after",
    "content": "<<if $hauntedHouseStarted>>[[Investigate the old house->Old House]]<</if>>"
  }]
}

Targets must already exist and cannot be protected story UI/initialization passages or passages tagged widget, grammar, script, or stylesheet. Restricted mode follows nested includes and uses a limited expression interpreter rather than JavaScript. Conditionals, switches, printing, links, controls, includes, literals, variables, safe operators, tags, and controlled variable assignment are supported; browser APIs, arbitrary calls, scripts, widgets, and executable-code registration are blocked. Restricted HTML and Markdown output is sanitized to remove event handlers, dangerous elements, and executable URLs. Save history retains base output only and reconstructs extension output from the mods that are currently enabled. See the bundled mod documentation for the complete protected list and policy.
